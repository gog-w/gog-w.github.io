本地/API 调用大模型，四个常见报错怎么根治

搭本地模型、接第三方 API 这阵子，报错就那么几类，但每次都要翻半天。按出现频率整理成一张排查表，下次照着对号入座。

429 Too Many Requests —— 请求超限

这不是你代码错了，是触发了速率限制。先别重试，按顺序查：

  • 是不是并发太高 / 重试太猛，加上请求间隔和退避；
  • 免费额度是不是被你一个人刷爆了；
  • 换个时间再试，高峰期尤其容易 429。

401 Unauthorized —— 认证没过

几乎都是 Key 的问题：

  • API Key 复制时多了空格或少了字符；
  • 请求头写法不对，要 Authorization: Bearer 你的key；
  • Key 被禁用、删了，或环境变量没真正生效（重启进程再读）。

400 Bad Request / 序列化错误

请求发出去了，但格式服务器不认：

多半是 messages 结构不对——角色字段要么是 system/user/assistant，content 是空或类型错。把请求体打印出来，对照官方文档逐字段核对。

No credits remaining —— 余额耗尽

API Key 没问题，就是账户没钱了。先去控制台看余额和用量；别在代码里死磕，先充值或换 Key。

排查顺序（建议）

  1. 看状态码：4xx 先看自己的请求，429/401 先看 Key 和额度；
  2. 把发出去的完整请求体打印出来，肉眼对文档；
  3. 用 curl 或官方调试台发一条最简请求，通了再回代码里对比。
